1)Difference between HTTP and HTTPS.
HTTP (HyperText Transfer Protocol) is an application-layer protocol used for transferring hypertext (HTML) and other resources over the web. It operates over port 80 and sends data in plain text, making it vulnerable to interception and tampering. HTTP is stateless, meaning each request is independent and does not retain session information without additional mechanisms like cookies or sessions.

HTTPS (HyperText Transfer Protocol Secure) is the secure version of HTTP. It uses TLS/SSL encryption to protect data in transit, ensuring confidentiality, integrity, and authentication. HTTPS operates over port 443 and is essential for sensitive transactions like online banking, e-commerce, and login forms.


2)Define web architecture.
Web architecture refers to the overall structure of a website or web application, including the way it is designed, implemented, and deployed. It involves the use of technologies and protocols such as HTML, CSS, JavaScript, and HTTP to build and deliver web pages and applications to users.

Web architecture consists of several components, including the client, the server, the network, and the database. The client is the web browser or application that the user interacts with, and the server is the computer or group of computers that host the website or web application. The network is the infrastructure that connects the client and the server, such as the internet. The database is a collection of data that is used to store and retrieve information for the website or web application.

9)Explore npm and npx
npm is a package manager for installing and managing Node.js dependencies, while npx is a tool for executing Node.js packages directly without needing a global installation. In short: npm installs, npx runs.
npm (Node Package Manager)
•	Introduced in 2010, developed by Isaac Z. Schlueter.
•	Comes bundled with Node.js installation.
•	Manages local and global dependencies.
•	Provides commands like:
o	npm install <package> → installs a package locally.
o	npm install -g <package> → installs globally.
o	npm run <script> → runs scripts defined in package.json.
⚡ npx (Node Package Execute)
•	Introduced with npm v5.2.0 (2017).
•	Allows execution of packages without installing them globally.
•	Useful for one-time commands or project generators.
•	Examples:
o	npx create-react-app my-app → scaffolds a React project.
o	npx eslint . → runs ESLint without global install.
•	Helps avoid version conflicts by running the exact package version specified in the project.
✅ When to Use Each
•	Use npm when you want to add dependencies to your project and manage them long-term.
•	Use npx when you want to execute a package immediately without cluttering your global environment.
 Risks & Considerations
•	npm: Installing too many global packages can cause version conflicts.
•	npx: Each execution may download packages temporarily, which can be slower if repeated often.
•	Best practice: Use npm for project dependencies, npx for one-off executions or generators.

10)Define CDN
A CDN (Content Delivery Network) is a system of distributed servers around the world that deliver web content to users faster and more reliably.
In plain terms: instead of everyone hitting one central server, a CDN serves content from the server closest to the user, reducing load time and strain.
What CDNs do
•	 Speed up websites (lower latency)
•	 Reduce distance between user and data
•	 Improve reliability & security (DDoS protection, redundancy)
•	 Lower bandwidth costs for the main server
Common content served by CDNs
•	Images, videos, audio
•	CSS & JavaScript files
•	Web pages and APIs
•	Software downloads
Popular CDN examples
•	Cloudflare
•	Akamai
•	Fastly
•	Amazon CloudFront
One-liner definition:
A CDN is a global network of servers that delivers content to users from the nearest location for faster and more reliable performance.

The smallest executable JavaScript file for the web is a single semicolon (;), which is syntactically valid and runs without errors in any browser's JS engine.

JavaScript architecture usually means how JS code is organized and executed, from runtime behavior to app structure.
There are two big layers to think about:
1.	JavaScript runtime architecture (how JS runs)
2.	Application architecture (how JS apps are structured)

2️⃣ JavaScript Runtime Architecture (how JS actually runs)
 Core components
1. Call Stack
•	Executes JS code line by line
•	Single-threaded (one thing at a time)
function a() {
  b();
}
function b() {
  console.log("Hi");
}

2. Heap

3. Web APIs (Browser / Node)
JS itself can’t do async things like:
•	setTimeout
•	HTTP requests (fetch)
•	DOM events
These are handled by Web APIs, not the JS engine.

4. Callback Queue / Task Queue
•	Stores callbacks waiting to run
•	Example: setTimeout

5. Microtask Queue
•	Higher priority than callback queue
•	Used by:
o	Promise.then
o	async/await

6. Event Loop
The boss
It:
1.	Checks if the call stack is empty
2.	Runs microtasks first
3.	Then runs callback queue tasks
console.log("A");

setTimeout(() => console.log("B"), 0);

Promise.resolve().then(() => console.log("C"));

console.log("D");

A
D
C
B

14) How does asynchronization works in JS

JavaScript is single-threaded, so async work is handled by delegating tasks, then resuming them later using the event loop.

1️⃣ Why JS needs async at all
If JS were only synchronous:
while (true) {}
👉 Browser freezes. No clicks. No UI. Dead.
Async lets JS:
•	Wait for timers
•	Handle network requests
•	React to user events
without blocking the main thread

2️⃣ The main players (memorize these)
Call Stack
•	Runs synchronous code
•	One function at a time


🌐 Web APIs (or Node APIs)
Handle async tasks:
•	setTimeout
•	fetch
•	DOM events
•	File system (Node)
JS hands off async work here.

📬 Queues
There are two queues:
1. Microtask Queue (HIGH priority)
•	Promise.then
•	catch
•	finally
•	async/await
2. Callback / Task Queue (LOW priority)
•	setTimeout
•	setInterval
•	DOM events

🔁 Event Loop
The coordinator:
1.	Waits until call stack is empty
2.	Executes all microtasks
3.	Executes one task from callback queue
4.	Repeats forever

3️⃣ Step-by-step example (IMPORTANT)
console.log("Start");

setTimeout(() => {
  console.log("Timeout");
}, 0);

Promise.resolve().then(() => {
  console.log("Promise");
});

console.log("End");
Execution order:
1. Call stack
Start
End
2. Web APIs
•	setTimeout registered
•	Promise resolved
3. Queues
•	Microtask queue → Promise
•	Callback queue → setTimeout
4. Event loop
Microtasks first, then callbacks
✅ Output:
Start
End
Promise
Timeout

4️⃣ async / await (syntactic sugar )
async function fetchData() {
  console.log("A");

  await fetch(url);
  console.log("B");
}
What actually happens:
•	fetch() runs async
•	Function pauses
•	Rest of the function is placed in microtask queue
•	Call stack is freed
So this:
await something();
≈
something().then(() => {
  // continue execution
});

5️⃣ Real-world async flow (fetch example)
fetch("/api/user")
  .then(res => res.json())
  .then(data => console.log(data))
  .catch(err => console.error(err));
Flow:
1.	Request sent via Web API
2.	JS continues running
3.	Response arrives
4.	Promise resolves
5.	.then() runs via microtask queue

6️⃣ Common async traps 
❌ Blocking the event loop
while (true) {} // freezes everything

❌ Thinking setTimeout(fn, 0) runs immediately
It doesn’t. It runs after:
•	Current stack
•	All microtasks

❌ Forgetting await
const data = fetch(url); // Promise, not data
7️⃣ Mental model (remember this)
Think of JS as:
“I’ll start the async job, and call you back when it’s done.”
JS never waits.
It just continues and revisits later.
8️⃣ TL;DR
•	JS is single-threaded
•	Async work is handled by Web/Node APIs
•	Promises go to microtask queue
•	Timers/events go to callback queue
•	Event loop decides execution order

15) identify the difference between spread operator and rest operator along with the use case

🔹 Core difference (one line)
•	Spread operator → expands values
•	Rest operator → collects values
Same syntax. Different jobs.

1️⃣ Spread Operator (...) — EXPAND
What it does
Takes an iterable (array, object, string) and spreads it out into individual values.

📌 Use cases for Spread
✅ Copy arrays or objects (no mutation)
const arr = [1, 2, 3];
const copy = [...arr];
const user = { name: "Sam" };
const clone = { ...user };

✅ Merge arrays
const a = [1, 2];
const b = [3, 4];

const merged = [...a, ...b];

✅ Merge objects
const defaults = { theme: "dark" };
const settings = { fontSize: 16 };

const config = { ...defaults, ...settings };
Later properties override earlier ones.

✅ Pass arguments to a function
const nums = [5, 10];

Math.max(...nums); // 10

✅ Convert string to array
[..."hello"]; // ['h','e','l','l','o']

2️⃣ Rest Operator (...) — COLLECT
What it does
Collects multiple values into a single array or object.


📌 Use cases for Rest
✅ Function parameters (variable arguments)
function sum(...numbers) {
  return numbers.reduce((a, b) => a + b, 0);
}

sum(1, 2, 3, 4);

✅ Destructuring arrays
const [first, ...rest] = [10, 20, 30, 40];

first; // 10
rest;  // [20, 30, 40]

✅ Destructuring objects
const user = { name: "Alex", age: 25, city: "NY" };

const { name, ...details } = user;

details; // { age: 25, city: "NY" }

3️⃣ Side-by-side comparison
Feature	Spread Operator	Rest Operator
Purpose	Expand values	Collect values
Used in	Function calls, arrays, objects	Function params, destructuring
Output	Individual elements	Array / object
Direction	One → many	Many → one



4️⃣ Key rule to remember 🧠
If ... is on the RIGHT side → Spread
If ... is on the LEFT side → Rest
Examples:
fn(...arr);     // spread
function fn(...args) {} // rest

5️⃣ Real-world example (combined)
function createUser(id, ...roles) {
  return {
    id,
    roles: [...roles] // rest → spread
  };
}

createUser(1, "admin", "editor");

6️⃣ Common mistakes ❌
•	❌ Using rest outside function params or destructuring
•	❌ Expecting spread to deep-copy objects (it’s shallow)
________________________________________
7️⃣ TL;DR
•	Same syntax ...
•	Spread = expand
•	Rest = collect
•	Context decides behavior
